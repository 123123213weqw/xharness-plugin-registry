# Strategy details

## TDD and maintenance
Anchor immutable meaningful test bytes for red, green and refactor. Record chronological real commands/source hashes and right-reason failures. Choose state-based or interaction-based doubles for the API contract, not ideology. Triangulate cases before generalizing; keep feedback fast without omitting critical branches. Team cycle/compliance metrics require actual time-series observations.

## Layer selection
Unit tests isolate logic; contract/integration tests validate real boundaries; UI/browser/mobile tests need actual installed runtime/device/framework; accessibility checks inspect real DOM/behavior. Performance/load/SLA/APM/RUM, chaos and canary tests need a separate authorized controlled environment and measurable baseline. Statistical experiments and fuzzing require their own repeatable protocol. Missing tools/accounts keep those layers pending.

## Data and delivery
Use synthetic non-sensitive data, deterministic clocks/seeds and ownership cleanup. Never silently move production records into tests. CI commands must match actual project runner/install constraints; parallelization requires state isolation and resource bounds. Aggregate actual results/skips/coverage and ownership for flaky/slow tests. Docker/Kubernetes or cloud-farm templates are planning artifacts, not live orchestration.

## External AI and metrics
Self-healing/visual/low-code/predictive tools may be evaluated only through installed available systems and real returned evidence. No vendor identity/model persona is supplied by this native guidance. Keep quality/ROI/performance forecasts explicitly hypothetical and report current constraints, not fictional dashboards or team adoption.
